# 视觉规格与提示词

只填与当前内容有关的部分。以下是提示词组织方式，不是工具参数。

## 内容到图形的映射

| 原文关系 | 合适的视觉 | 核对点 |
| --- | --- | --- |
| 分类、组成 | 分支、容器、嵌套 | 包含关系是否真实；独立字段不要放错容器 |
| 信息供给、输入输出 | 多源汇流、管线、文档与接口 | 谁提供什么，流向谁 |
| 执行步骤、交互协议 | 流程、泳道、简短时序 | 谁决策、谁执行、谁返回；结束条件 |
| 反馈与迭代 | 闭环与退出分支 | 回到哪个阶段，何时继续或终止 |
| 并行与依赖 | 分叉、汇合、先后连线 | 并行是否确实无数据依赖 |
| 稳定与变化、复用与失效 | 对齐条带、变化点、局部重算色块 | 失效边界，不要把局部失效画成全部失效 |
| 错误与改进 | 错误→替代做法、前后对照 | 替代措施在原文中有依据 |
| 研究与实践 | 主图加次级研究角标 | 研究机制不可画成生产默认能力 |

## 可填充提示词

```text
Use case: infographic-diagram / scientific-educational
任务：依据下述已核对的内容蓝图，生成一张可放大阅读的知识图解。
语言：[材料主要语言]；标题：“[确切主题]”；副标题：“[章节范围与主线]”。
用途：[阅读复习 / 分享 / 汇报]。
视觉：[按用户要求或内容选择风格]；文字清晰，层级明确，色彩对应知识组。
版式：[根据知识结构安排，预留主图、关系图、边界与来源位置]。

必须呈现的内容：
1. [知识组名称、核心观点、必要限定]
   图形：[节点 / 图标 / 容器]
   关系：[源节点 → 目标节点；箭头标签与含义]
   必须逐字渲染：“[重要标签]”。
2. [下一知识组，同上]
共享主线：[各组如何衔接；哪些为并列、因果或约束]。
示例：[原文示例及其用途，保持条件]。
边界：[适用条件、例外、研究阶段说明]。
来源页脚：“[作者 / 文题 / 章节 / 书内页码；只写已确认信息]”。

限制：不要虚构数值或扩展不在范围内的模块。
不要只将段落放进卡片，使用图形承担解释；避免装饰挤占知识标签。
连线不要产生歧义，循环保留明确退出条件；文字不要重叠、乱码或截断。
```

## 内容蓝图示例：上下文工程

这个示例说明怎样选取关系；处理新材料时重新读原文，不套用知识点。

- **信息供给**：代码信息、流程规范、环境描述 → 本轮上下文 → 模型决策。配合隐性经验 → 文档记录 → 可检索知识的链路。
- **接口与循环**：messages 中四种 role；tools 在其外。框架构造请求 → 模型生成调用 → 框架执行工具 → 追加结果 → 再次请求；无工具调用时转向最终回复。
- **缓存机制**：注意力 Q–K 匹配与 V 加权；区分单次推理内 KV 复用和跨请求前缀复用。
- **共同布局**：稳定规则及工具定义 ＋ 追加轨迹。两条对齐 token 序列对比前缀稳定与中途改动，标明改动前可复用、从首个不同 token 起重算。
- **边界**：环境描述不等于环境本身；API 字段不等于序列化后的物理布局；可编辑缓存作为研究旁注。

## 局部修正提示词

```text
编辑目标：[已查看的生成图]。
只修改：[列名、节点名、区域位置，必要时说明实际图像坐标]。
问题：[可观测的问题]。
替换为以下完整文本：“[替换文字]”。
关系修正：[明确连线起点、终点、箭头方向]。
保留：[其他文字、图标、布局、风格、配色]。
验收：[必须可观察到的修正结果]。
```

不要只说“更准确”“更丰富”后重画全图。局部修正仍需要查看输出；调用成功不代表已修好。
